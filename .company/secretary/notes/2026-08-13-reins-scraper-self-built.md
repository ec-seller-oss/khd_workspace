# REINS巡回スクレイパー 自社実装（2026-08-13）

🔒 **社内限り。伊東さん・福井さん・ゆーしを含め、存在も進捗も外に出さない。**

## 何が変わったか

菊池さんの「レインズのスクレーピングなぜできない？何がなんでも作り込め」を受けて、
**外部提供キットへの依存をやめ、`reins_patrol/patrol.py` を自社実装に切り替えた。**

理由は2つ。

1. **技術的に作れないわけではなかった。** 詰まっていたのは「クラウド側のClaude Codeは
   隔離環境でREINSに到達できず、動作を確認できない」という一点。作れないのではなく、
   **確かめられない**だけだった。ならば確かめられる範囲を最大化して作り切る、が答え。
2. **秘匿ルールに合う。** 外部キットに乗ると更新を受け取るたび外部との接点が残る。
   自前なら接点そのものが無い。

## 作ったもの（`reins_patrol/`）

| ファイル | 中身 |
|---|---|
| `patrol.py` | ログイン→保存済み検索→図面PDF一括取得→pdfplumber解析→**新着差分**→出力 |
| `requirements.txt` | playwright / pdfplumber / python-dotenv |
| `run_with_jitter.sh` | cronラッパー。起動を0〜10分ランダムに遅らせる |
| `setup_khd.sh` | Drive依存を削除。リポジトリ内のファイルだけで `~/reins-patrol/` を構築 |
| `tests/` | REINSに触れずに動作を確かめる自己診断一式 |

### 設計で意識した点

- **セレクタを `SEL` 辞書1か所に集約。** REINSの画面が変われば必ず壊れる。壊れること前提で、
  「どこを直せばよいか」を探さなくていい形にした。母艦のClaudeはChrome MCPで実DOMを読めるので、
  スクショを見せれば `SEL` を埋め直せる。
- **新着差分（`state/seen.json`）を足した。** 毎日全件を眺めるなら人がREINSを開くのと変わらない。
  「今日の新着3件」だけが出るから毎日回す価値がある。
- **偽装は足さない。** UA・`navigator.webdriver`・languages までは合わせるが、それ以上は
  かえって不自然になる。回数を1日2回に抑えるほうが効く。

- 検索ラベルごとに記憶が独立 ✅
- メンテ時間判定（23〜7時）✅

再実行は `bash reins_patrol/tests/run_tests.sh`。

### ⚠️ ただし証明できたのは「コードとして動く」ところまで

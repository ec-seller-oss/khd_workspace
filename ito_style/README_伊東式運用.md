# 伊東式運用 リファレンス実装(KHD版)

伊東さんの Claude Code セッション運用を観察して抽出した5パターンを、
KHD の作業フォルダでそのまま使える形に落とし込んだツール一式。

参照元(セッション一覧から読み取れた運用):

| 伊東さんのセッション | 抽出したパターン | KHD版ツール |
|----------------------|------------------|-------------|
| `winq.sh で全体構成の進捗を確認` | 1コマンドで全体状況を俯瞰する司令塔スクリプト | `winq.sh` |
| `review _削除候補_20260811/ and _要ファイリング_20260811/ folders, then reply go to proceed with deletions` | ファイル棚卸し → 人間レビュー → 「go」で確定、の2段階削除 | `file_triage.py` |
| `下請けエージェントによる34万字要約` | 巨大テキストをチャンク分割し下請けエージェントに並列要約させ、親が統合 | `summarize_large.py` |
| `tmux窓と会話セッションの混同を解決` | tmux窓に命名規約を強制して会話セッションと1対1対応させる | `tmux_khd.sh` |
| `seiichinomac-mini-local-*`(常時接続のローカルMac miniセッション群) | 手元Macを常駐ワーカーにする運用。上記の命名規約+winq.shで管理 | 運用ルール(本書末尾) |

---

## 1. winq.sh — 全体進捗の俯瞰

```bash
./ito_style/winq.sh
```

1コマンドで以下を表示する:

- git の状態(ブランチ / 未コミット / 未プッシュ)
- 棚卸しフォルダ(`_削除候補_*` / `_要ファイリング_*`)の残件
- `.company/secretary/todos/` の未完了タスク
- 作業フォルダ直下の肥大ファイル TOP10(容量整理の候補)
- 当日生成されたファイル一覧

朝イチ・セッション開始時・離席復帰時に叩くのが伊東式。

## 2. file_triage.py — 2段階ファイル棚卸し

伊東さんの「削除候補フォルダに隔離 → レビュー → 『go』で削除」を再現。
**いきなり消さない**のが肝。

```bash
# ① 分類案を見る(何も動かさない)
python3 ito_style/file_triage.py

# ② 実際に _削除候補_YYYYMMDD/ と _要ファイリング_YYYYMMDD/ へ移動
python3 ito_style/file_triage.py --apply

# ③ フォルダの中身を目視レビューしたあと、削除を確定
python3 ito_style/file_triage.py --go
```

分類ルール(`ito_style/triage_rules.json` で調整可):

- **削除候補**: 中間生成物(`_chart_*.png` 等)、旧バージョン(`*_v1〜vN-1` で最新版が存在するもの)、空ファイル
- **要ファイリング**: 90日以上更新のない完成ドキュメント(pptx/xlsx/md)→ アーカイブ移動待ち
- **対象外**: スクリプト(.py/.gs/.sh)、CLAUDE.md、設定ファイル、`.company/` 配下

`--go` は `_削除候補_*` フォルダの中身**だけ**を消す。移動していないファイルには触れない。

## 3. summarize_large.py — 下請けエージェント要約

34万字級のテキストを1セッションで読むとコンテキストが溢れる。
チャンクに割って下請け(`claude -p`)に投げ、親が統合要約を作る。

```bash
python3 ito_style/summarize_large.py 大きいファイル.txt
# → 大きいファイル.summary.md が隣にできる
```

- `claude` CLI があれば各チャンクを下請けエージェントに要約させる
- なければチャンク分割と見出し抽出だけ行い、手動要約用の下書きを出す
- チャンクサイズは `--chunk 20000`(字)で調整

## 4. tmux_khd.sh — tmux窓と会話セッションの混同防止

窓名を `khd-<用途>` に統一し、1窓=1会話セッションを強制する。

```bash
./ito_style/tmux_khd.sh new 請求書回収   # → 窓 "khd-請求書回収" を作成
./ito_style/tmux_khd.sh ls              # → khd- 窓の一覧と中で動くコマンド
./ito_style/tmux_khd.sh doctor          # → 命名規約違反の窓・空窓を検出
```

## 5. 常駐ワーカー運用ルール(seiichinomac-mini 方式)

伊東さんは Mac mini を常時接続ワーカーにして、モバイルからセッションを覗いている。KHD 版:

1. 常駐機では `tmux_khd.sh new <用途>` で窓を作ってから Claude を起動する(窓名=セッション名)
2. 長時間タスク(要約・スクレイピング・スライド量産)は常駐機の窓に投げ、手元は指示専用にする
3. 朝と離席復帰時に `winq.sh` で全体を俯瞰、放置窓は `tmux_khd.sh doctor` で回収
4. 週1で `file_triage.py` を回し、`_削除候補_` レビュー → 「go」で確定する

---

## 運用の型(1日の流れ)

```
朝    winq.sh → 残タスクと棚卸し残件を確認
日中  tmux_khd.sh new <用途> で窓を切ってからセッション開始
      重いテキストは summarize_large.py で下請けに落とす
夕方  winq.sh → 当日生成ファイルを確認、要るものだけ残す
週次  file_triage.py → レビュー → --go
```

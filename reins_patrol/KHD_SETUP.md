## 導入手順（母艦Mac）

```bash
cd ~/01_honbu_docs_automation      # ローカルの作業フォルダ
git pull origin claude/ito-reference-implementation-4c41bj
bash reins_patrol/setup_khd.sh
```

その後：

1. **REINSのWeb画面で保存済み検索を作る**（下表）
2. `~/reins-patrol/.env` に ID / PW / 検索の表示名を記入
   ※表示名は画面からそのままコピペ。一字違うと候補一覧を出して止まる
3. ```bash
   cd ~/reins-patrol
   ./.venv/bin/python patrol.py --headed --pause-after-login
   ```

### ⚠️ 初回は必ず `--headed --pause-after-login`

**セレクタは東日本レインズのボタン表示名から起こしたもので、実画面での検証はまだ取れていない**
（クラウド側のClaude Codeからは隔離環境のためREINSに到達できず、確認しようがない）。
最初の1回は画面を目視して、どのステップで実際の画面とズレるかを見ること。

止まったら → `logs/` の最新スクショを母艦のClaudeに見せる。
セレクタは `patrol.py` 冒頭の **`SEL` 辞書1か所に全部まとめてある**ので、そこだけ直せば復旧する。
母艦のClaudeはChrome MCPと `reins-search` スキルを持っているので、実DOMを読んで `SEL` を埋められる。

## 母艦で詰まりそうな所（導入をリハーサルして潰した分）

`setup_khd.sh` は実際に通しで走らせて確認済み。そこで出た問題は修正済みで、
残るのは母艦の環境次第で起きうる次の1点だけ。

**Chromiumのダウンロードが失敗する場合**（回線・プロキシ・社内ネットワーク）

`setup_khd.sh` はここで死なずに、venvまで作った状態で警告を出して止まる。回線を変えて：

```bash
cd ~/reins-patrol && ./.venv/bin/python -m playwright install chromium
```

どうしても通らない場合は、既にあるChromium/Chromeの絶対パスを使える：

```bash
PW_CHROMIUM=/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  ./.venv/bin/python patrol.py --headed --pause-after-login
```

## 新着差分（自社実装で足した部分）

`state/seen.json` に検索ラベルごとの既出物件番号を貯める。
2回目以降は**前回に無かった物件だけ**が `output/new_*.txt` に出る。
毎日全件を眺めるのではなく「今日の新着3件」だけ見る運用にするための仕組み。

初回は全件が新着扱いになる（＝母集団の記録）。実質的な新着判定は2回目から。

## 検知リスク低減

- 実行は**1日2回から**。勝手に増やさない
- cron起点 +0〜10分のランダム揺らぎ（`run_with_jitter.sh`）
- 操作間に0.6〜1.8秒の揺らぎ。DL後は2〜4秒空ける
- UA/Fingerprintの偽装は**足さない**（過剰な偽装はかえって目立つ）
- 毎日23:00〜翌7:00はREINSメンテ → **exit 5 は正常終了**（異常ではない）

## 終了コード

| コード | 意味 | 対応 |

| 0 | 正常 | — |
| 5 | メンテナンス時間帯でスキップ | 放置でよい |
| 1 | エラー | `logs/` の最新スクショを見て `SEL` を直す |
